## О проекте

Это учебный бэкенд-сервис, который начинался с простого API на Node.js, а в итоге превратился в полноценное микросервисное приложение в контейнерах. В процессе разработки база данных сменилась с PostgreSQL на MongoDB, добавилось кэширование через Redis, появилась балансировка нагрузки через Nginx, а затем всё приложение упаковали в Docker и научились запускать одной командой в WSL.

## Практические занятия 19-20: Базы данных (PostgreSQL - MongoDB)

Сначала я подключил к серверу реляционную базу PostgreSQL через библиотеки `pg` и Sequelize. Создал таблицу пользователей (id, имя, фамилия, возраст, время создания и обновления), написал полный набор CRUD-эндпоинтов: создание, получение списка, получение одного пользователя, обновление и удаление. Потом переписал тот же API для MongoDB с использованием Mongoose — схема осталась похожей, но база стала документоориентированной и гибкой.

## Практическое занятие 21: Кэширование с Redis

Добавил Redis, чтобы ускорить частые запросы. GET-запросы на получение списка пользователей (кеш на 1 минуту) и товаров (кеш на 10 минут) сначала проверяют Redis — если данные есть, они возвращаются мгновенно из оперативной памяти. Если нет — сервер идёт в базу, отдаёт ответ и сохраняет его в Redis. При изменении или удалении данных кеш очищается, чтобы клиенты не видели устаревшую информацию.

## Практическое занятие 22: Балансировка нагрузки

Я запустил несколько одинаковых backend-серверов на разных портах и настроил Nginx в качестве балансировщика. Nginx распределяет входящие запросы по кругу (Round Robin), а с помощью параметров `max_fails` и `fail_timeout` проверяет, жив ли сервер. Если один из контейнеров остановить, Nginx перестаёт отправлять на него трафик и продолжает работать через оставшиеся. Ещё я попробовал HAProxy — он делает то же самое, но с другими настройками.

## Практическое занятие 23: Контейнеризация с Docker

Всё приложение упаковал в контейнеры. Написал Dockerfile для каждого сервиса на основе лёгкого образа `node:18-alpine`, создал файл `docker-compose.yml`, где описал API-шлюз, сервис пользователей, сервис заказов, а также добавил Nginx, Redis и базы данных как отдельные контейнеры. Все сервисы объединены в одну сеть и общаются друг с другом по именам. Проект запускается командой `docker compose up --build` в WSL, останавливается и чистится тоже одной командой. Данные баз сохраняются между перезапусками благодаря томам.

## Технологии

Node.js, Express, PostgreSQL, MongoDB, Redis, Nginx, HAProxy, Docker, Docker Compose, WSL.

## Что в итоге

Готовый микросервисный проект, который поднимается изолированно на любой машине с Docker. Он умеет хранить данные в двух типах баз, кешировать частые запросы, распределять нагрузку между несколькими экземплярами, переживать падение одного из серверов и восстанавливаться без ручного вмешательства. Весь код писался и тестировался в Ubuntu через WSL прямо на Windows.
